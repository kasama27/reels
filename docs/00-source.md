# ข้อมูลต้นทาง (Source Requirements)

บันทึกสิ่งที่ใช้เป็นข้อมูลต้นทางของชุดเอกสารนี้ เอกสารอื่นในชุดตีความและขยายจากไฟล์นี้

ชุดเอกสารนี้ต่างจากปกติ: ระบบ **พัฒนาไปแล้วบางส่วน** จึงเป็นการถอดเอกสารจากระบบที่มีอยู่ (as-built) แล้วเสนอแนวทางจัดระบบใหม่ ไม่ได้เขียนจาก TOR

| รายการ | ค่า |
|---|---|
| ได้รับเมื่อ | 28 ต.ค. 2026 |
| ได้รับจาก | เจ้าของระบบเอง (ตามที่ผู้ใช้ยืนยันในแชต ประเด็นที่ 1) |
| รูปแบบ | โค้ดระบบในโฟลเดอร์ `reels/` + ข้อความในแชต + ภาพหน้าจอ 1 รูป (หน้าซีรีส์) |

## 1. สิ่งที่ได้รับ

### 1.1 โค้ดระบบที่อ่าน
| ไฟล์ | สรุป |
|---|---|
| `server.js` | เซิร์ฟเวอร์ HTTP และเส้นทาง API ทั้งหมด (ประมาณ 1,300 บรรทัด) |
| `lib/db.js` | ฐานข้อมูล SQLite: คลิป ฟีด สินค้า |
| `lib/story.js` | โปรเจกต์เรื่อง ตัวละคร/สถานที่/ของประกอบ ช็อต พรอมต์ |
| `lib/series.js` | ซีรีส์ งานผลิตตอน การลงต่อแพลตฟอร์ม และกติกาความปลอดภัย |
| `lib/ai.js`, `lib/claude-cli.js` | เรียก Claude (ผ่านบัญชีที่ล็อกอิน หรือคีย์ API) |
| `lib/tts.js`, `lib/tts.ps1` | เสียงบรรยาย 3 ทาง (Windows, Google, Gemini) |
| `lib/render.js` | ตัวเรนเดอร์สำรองด้วย ffmpeg |
| `lib/promptimport.js` | แยกสคริปต์สตอรีบอร์ดเป็นช็อตโดยไม่ใช้ AI |
| `lib/feeds.js`, `lib/pondy.js`, `lib/brand.js`, `lib/config.js`, `lib/ctx.js` | ข่าว RSS, นำเข้าสินค้าจากมือถือ, สไตล์เพจ, ค่าตั้ง, บริบทคำขอ |
| `public/index.html`, `app.js`, `story.js`, `series.html`, `series.js` | หน้าจอทั้งหมด |
| `public/render.js`, `tplb.js` | ตัวเรนเดอร์หลักในเบราว์เซอร์ และเทมเพลต B |
| `extension/` | ส่วนเสริม Chrome ช่วยแนบรูปและคลิปเข้าช็อต |
| `README.md` (ฉบับเดิม) | สำรองไว้ที่ `backups/README-before-design-docs-20261028.md` |

### 1.2 ภาพหน้าจอ
หน้าซีรีส์รายวัน (`series.html`) 1 รูป แสดงฟอร์มเพิ่มซีรีส์ การ์ดซีรีส์ "คัมภีร์วิถีเซียน" และตารางตอน EP.1

### 1.3 ผลการสอบถามผู้ใช้ก่อนเขียน
ผู้ใช้ตอบข้อเสนอ 7 ข้อและ 2 คำถามขอบเขต ดูหัวข้อ 2

## 3. สิ่งที่ต้นทางไม่ได้ระบุ

- ช่วงบทนิยายของแต่ละตอนซีรีส์ (ประเด็นที่ 2 และ 14)
- ช่องทางแจ้งเตือนเมื่องานอัตโนมัติล้ม (ประเด็นที่ 17)
- เบราว์เซอร์ที่ใช้รันงานอัตโนมัติ และวิธีไม่ให้การล็อกอินหลุด (ประเด็นที่ 12)
- ระดับความดังของเสียงที่ยอมรับได้ ผู้ใช้ยังไม่ได้ฟังคลิปตัวอย่างเสร็จ (ประเด็นที่ 16)
