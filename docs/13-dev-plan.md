# แผนพัฒนาระบบ (Development Plan)

เป้าหมาย: พาระบบจากสถานะปัจจุบัน (ผลิตตอนได้ถึงพร้อมโพสต์) ไปสู่การผลิตและโพสต์ซีรีส์รายวันอัตโนมัติบน Facebook แล้ว YouTube โดยจัดระบบที่ซ้ำซ้อนให้เรียบพอที่จะดูแลง่าย

ระยะเวลาเป็นค่าประมาณสำหรับผู้พัฒนาหนึ่งคน (ผู้ช่วย AI ทำงานร่วมกับเจ้าของ) ประมาณจากความเร็วของงานที่ผ่านมาในโครงการนี้ซึ่งแต่ละขั้นใช้ราวครึ่งวันหรือน้อยกว่า ปรับตามจริง ขั้นที่พึ่งเว็บภายนอกอาจใช้นานกว่าเพราะต้องทดลองกับของจริง

> **อัปเดต 30 ต.ค. 2026:** งานหลักเปลี่ยนเป็นคลิปแนะนำสินค้า (ดู docs/14-product-clips.md และ README.md) คลังสินค้ากลับมาใช้แล้ว ถ้าข้อความในไฟล์นี้ขัดกับ README/14 ให้เชื่อ README/14

## เฟส 1: ปิดช่องโหว่และจัดระเบียบที่กระทบงานอัตโนมัติ (ประมาณ 1 ถึง 2 วัน)

**เป้าหมาย:** งานตอนไม่ค้างผิดสถานะ ชื่อสถานะและฟิลด์สอดคล้องกัน ก่อนต่อระบบโพสต์

| งาน | ทีม | อ้างอิง |
|---|---|---|
| เรียกซิงก์สถานะงานตอนหลังลบช็อตและหลังให้ AI แบ่งช็อตใหม่ | ผู้พัฒนาระบบหลัก | 12-decisions.md ประเด็นที่ 18 |
| เปลี่ยนชื่อสถานะบนหน้าจอตามชุดคำรวม (ไม่แตะฐานข้อมูล) | ผู้พัฒนาหน้าเว็บ | 03-flows.md "ชุดคำสถานะที่ผู้ใช้เห็น" ประเด็นที่ 3 |
| เพิ่มฟิลด์ช่วงบทนิยายต่อตอน และให้ skill อ่านฟิลด์นี้ | ผู้พัฒนาระบบหลัก | ประเด็นที่ 2 และ 14 |
| เพิ่มฟิลด์รหัสเพจ/รหัสช่อง และตรวจชื่อกับชื่อจริง | ผู้พัฒนาระบบหลัก และเจ้าของ | ประเด็นที่ 13 |
| เมื่อการลงสำเร็จให้ตั้งคลิปเป็น "โพสต์แล้ว" (ถ้าเจ้าของเห็นชอบ) | ผู้พัฒนาระบบหลัก | ประเด็นที่ 4 |
| เพิ่ม Gemini ในรายการผู้สร้างรูป | ผู้พัฒนาระบบหลัก | 04-architecture.md ข้อ 7 |

**เกณฑ์ผ่าน:** ลบช็อตหรือแบ่งช็อตใหม่แล้วสถานะงานตอนถูกต้อง (ทดสอบด้วยข้อมูลจำลอง) ข้อความสถานะบนหน้าจอตรงตารางชุดคำ ฟิลด์ใหม่ใช้ได้ผ่าน API และหน้าซีรีส์ ผู้ยืนยัน: เจ้าของระบบ

## เฟส 2: ทางนำรูปเข้าแอปโดยไม่เด้งถาม (ประมาณ 1 ถึง 3 วัน ขึ้นกับทางที่เลือก)

**เป้าหมาย:** ผู้ช่วย AI นำรูปที่ได้จากผู้สร้างรูปเข้าช็อตได้โดยไม่ต้องให้เจ้าของกดบันทึกไฟล์

| งาน | ทีม | อ้างอิง |
|---|---|---|
| ตรวจค่าใช้จ่ายและความสามารถของ Gemini API สำหรับสร้างรูป (ถ้าเลือกทางนี้) | ผู้พัฒนาระบบหลัก และเจ้าของ | ประเด็นที่ 11, 07-image-generation.md |
| ทำทางที่เลือก: API สร้างรูป หรือขยายส่วนเสริม Chrome หรือ endpoint รับรูปแคบ | ผู้พัฒนาระบบหลัก | ประเด็นที่ 11, 09-ai-and-voice.md ข้อ 4 |
| ทดสอบกับ 1 ตอน 6 ช็อต ไม่ต้องมีการกดบันทึกไฟล์เลย | ผู้พัฒนาระบบหลัก | 07-image-generation.md ข้อ 6 |
| ปรับ skill และคู่มือขั้นตอนให้ใช้ทางใหม่ | ผู้พัฒนาระบบหลัก | `.claude/skills/reels-episode/SKILL.md` |

**เกณฑ์ผ่าน:** ตอนทดลอง 6 ช็อตได้รูปครบเข้าช็อตครบ โดยเจ้าของไม่ต้องกดอะไร และการล็อกอินหลุดทำให้หยุดพร้อมเหตุผล ผู้ยืนยัน: เจ้าของระบบ
